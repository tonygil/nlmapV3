What this tool does

The Taxonomy Mapper takes URLs from the Salesforce Knowledge base and automatically maps them to the correct Product → Domain → Segment → Topic classification using fuzzy keyword matching. This tells us which topic each help article covers so the taxonomy team can identify gaps and improve coverage.

Key principle The tool never invents topics — it only assigns topics that already exist in the taxonomy file. If an article doesn't match anything, it appears as UNMAPPED, which is useful information in itself.

1
Export articles from Salesforce

What to export

  • Go to Salesforce → Knowledge → Articles
  • Export as Knowledge__kav CSV
  • The file will have 482+ columns — this is normal, the tool handles it automatically
  • Only these columns are actually used: Knowledge_Url__c, Title, Summary, Answer__c, Data_Categories__c
About Data_Categories__c This column contains the product assignments (e.g. Adsolut_Account;ExpertM_Plus;Briljant_Account). The tool uses this to expand one article into multiple rows — one per product — so each article can match topics from all its relevant products. Belgium typically gains ~700 extra rows this way (1,809 unique URLs → 2,518 total rows).
2
Import the CSV into NLMap (Import SF CSV)

In the NLMap GUI

  1. Open NLMap: double-click launch_gui.bat or run python taxonomy_matcher_gui.py
  2. Go to the Setup tab
  3. Click the 📥 Import SF CSV button (purple, bottom bar)
  4. Select your Knowledge__kav.csv export file
  5. Set Country to BE
  6. Optionally select the taxonomy file for keyword ranking
  7. Click ▶ Import CSV

What happens automatically

  • Ignores the 476 junk columns
  • Extracts URLs from HTML anchor tags in the URL column
  • Converts internal Lightning URLs to public community URLs
  • Expands multi-product articles (using Data_Categories__c)
  • Extracts Keywords 1-12 from Title, Summary, and Answer content
  • Saves output as Semantic_BE_{datetime}.xlsx
✓ Output file location The file is saved in the same folder as the input CSV, named Semantic_BE_YYYYMMDD_HHMMSS.xlsx. Make a note of this path — you'll need it in the next steps.
3
Run the Taxonomy Match

In the Setup tab

  1. Set Country to BE
  2. Semantic File: browse to Semantic_BE_{datetime}.xlsx (from Step 2)
  3. Taxonomy File: browse to your BE taxonomy (e.g. countries/BE/taxonomy.xlsx)
  4. Leave Threshold at 80 (default)
  5. Leave Top Results per URL at 6 (default)
  6. Click ▶ Run Taxonomy Match
SettingRecommended valueNotes
CountryBELoads BE synonyms and config
Threshold80%Below 80 = too many false matches
Use SummaryOptionalAdds extra keywords from Summary column
Top Results per URL6Max rows per URL in output
Debug ModeOffOnly enable for troubleshooting individual URLs

How long does it take? With 2,518 BE rows at threshold 80, expect approximately 25–40 minutes. The Console tab shows live progress every 50 URLs.

Output

Results are saved as taxonomy_match_BE.xlsx (two sheets):

  • Results — one row per URL-Segment, with Topic_1, Topic_2…, Score, Relevance, Rank
  • Keyword Recommendations — near-miss keywords that almost matched, with suggested synonyms
4
Post-Run Synonym Review

After the match finishes, a Post-Run Synonym Review dialog opens automatically. It shows keywords that scored just below the 80% threshold — they almost matched a topic but didn't quite make it. You can approve them as synonyms to improve future match rates.

⚠ This is the most important step to get right Approving bad synonyms will cause false matches in every future run and are hard to undo. Take time to review each row carefully. When in doubt — dismiss it.

Decision guide — approve or dismiss?

🚨 The "Artikelen" problem — what's happening Every page on the Salesforce community site is technically "an article", so the site's navigation buttons (find article, read article, all articles) appear on every single page and get extracted as keywords. These phrases score ~76% against the "Artikelen" taxonomy topic (which is the legitimate software feature for managing knowledge base articles in Adsolut KMO-beheer). Do not approve any "artikel vind / lees / legt / leggen / willen / kunt" phrases. They are navigation noise, not content.

How to use the dialog

  1. Click Show URLs on any row you're unsure about — shows up to 5 sample URLs so you can judge whether the pages genuinely cover that topic
  2. Click the ✓ checkbox in the left column to select rows you want to approve
  3. Leave "artikel*" rows unchecked — they'll be dismissed automatically
  4. Click Approve Selected to add the checked synonyms to synonyms.json
  5. Run the taxonomy match again — your approved synonyms will now produce matches
💡 Iterative improvement You don't have to get this perfect in one pass. A typical cycle is: run match → approve a handful of clear synonyms → re-run match → match rate improves → fewer near-misses next time. After 3–4 cycles the match rate stabilises.
5
Run the Taxonomy Gap Analysis Report

The Gap Analysis Report identifies which taxonomy topics have never been matched by any URL, which topics appear in the output but don't exist in the taxonomy (phantom topics), and suggests synonym candidates for improving coverage.

In the Reports tab

  1. Click the Reports tab in the top navigation
  2. Scroll to the Taxonomy Gap Analysis Report section
  3. Set the three file fields:
FieldSelect this fileRequired?
Match Filetaxonomy_match_BE.xlsx (from Step 3)✓ Required

SemanticSemantic_BE_{datetime}.xlsx (from Step 2)Optional

  1. Click Generate Gap Analysis Report
  2. Wait for completion (typically 1–2 minutes)

6
View the Dashboard (no Excel needed)

The HTML dashboard lets you view the gap analysis results visually without needing Microsoft Excel installed. It works entirely in the browser and supports all countries.

First time only — generate the dashboard file

# Run once to create gap_analysis_dashboard.html python generate_gap_dashboard.py

This creates gap_analysis_dashboard.html in your project folder. You only need to do this once — the file can be reused for all future sessions and all countries.

Every time — open the dashboard and load your report

  1. Double-click gap_analysis_dashboard.html to open it in Edge or Chrome
  2. Click 📁 Select Excel File
  3. Browse to TAXONOMY_GAP_ANALYSIS_REPORT.xlsx
  4. The dashboard loads instantly — no further steps needed
  5. To switch country, click 📁 Load Different File in the top bar and select the other country's report
✓ What you'll see in the dashboard
  • Match Rate ring — colour-coded green/amber/red (≥80% / 60–79% / <60%)
  • 4 KPI cards — Never-Matched Topics, HIGH Priority Synonyms, Phantom Topics, Topics Covered
  • Match Rate Trend chart — shows improvement over multiple runs (needs 2+ reports)
  • Product Performance bar chart — match rate per product, sorted worst-first
  • Synonym Recommendations — HIGH priority items with suggested keywords
  • Never-Matched Topics table — filterable by product
  • Progress History — full run history, latest highlighted

Troubleshooting

ProblemLikely causeFix
Match rate very low (<50%) Synonyms.json needs more entries for BE topics Run 2–3 synonym review cycles, approving real topic names
"artikel*" phrases keep appearing Semantic file extracted before v3.19 noise filter Re-run Import SF CSV to get fresh keywords with noise filtering applied
Wrong product in output rows Product comes from taxonomy match, not the input file Normal — use synonyms to steer which topics (and therefore products) match
0 matches / file swap error Semantic and Taxonomy files are in the wrong fields Click "Swap Files" button or manually correct — Semantic has Keyword columns, Taxonomy has Topic columns
Match takes very long Normal for large datasets Use Max Rows = 100 and URL Filter for quick tests before running the full set
Dashboard shows no trend chart Only one Gap Analysis Report has been run Run the report again after the next synonym cycle — trend appears with 2+ data points
Gap report Excel "found a problem" Data contains control characters or very long strings This is handled automatically by the sanitize step — if it persists, report to the tool owner
