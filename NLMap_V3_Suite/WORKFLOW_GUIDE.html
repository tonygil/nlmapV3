What this tool does

Read this first — one paragraph overview

Taxonomy Mapper V3 takes a list of help-centre URLs (with extracted keywords) and maps each URL to one or more taxonomy topics — the structured set of product/domain/segment/topic combinations your organisation uses to classify content.

Matching is done by fuzzy string comparison (≥80% similarity by default) between keywords and topic names, with synonyms bridging gaps in language. The result is an Excel file showing every URL's matched topics, relevance score, and — for any URL that didn't match — the reason why.

The improvement loop is iterative: run → analyse unmapped rows → fix synonyms / product routing / noise phrases → re-run → repeat until the match rate target is reached.

Multi-country: BE · GB · NL · SE
Default threshold: 80%
Output: taxonomy_match_{CC}_{YYYYMMDD_HHMM}.xlsx

Order matters. Always do bulk fixes before row-by-row triage. One category_mapping.json entry can unblock 60+ articles instantly — doing that before opening unmapped_review.html means far fewer rows to triage. Check Gap Analysis → Product Breakdown to see which product has the most unmapped URLs and start there.

What to do with unmapped URLs

Every unmapped row has an Unmapped_Reason. Here's what each one means and how to fix it.

Look at the Unmapped_Reason column in the Results sheet
"No keywords extracted from row"

Meaning: All Keyword 1–12 columns are empty. The matcher had nothing to work with.

Fixes (in order):
  1. Check if the Content Keyword Extractor was run on this file. If not, run it first.
  2. Check if the source article has Title / Summary / Description content — content-less articles can't be mapped.
  3. If the URL is genuinely empty/noise, use unmapped_review.html → Remove to exclude it from the denominator.
"Product filter excluded matches (semantic Product: X)"

Meaning: The matcher did find topic matches, but they were all filtered out because the article's product didn't match the taxonomy product.

Check the Suggested_Product column — it shows which taxonomy product the best match belongs to, pre-populated in unmapped_review.html.

Fixes (in order):
  1. If Salesforce CSV import: the Data_Categories__c value isn't mapped — add it to category_mapping.json via the Category Mapping tab.
  2. If the product is a known alias (e.g. "Adsolut boekhouden" vs "Adsolut boekhouding"): add to product_synonyms in synonyms.json via the Synonym Editor.
  3. If the article genuinely covers multiple products, set the mapping to the canonical taxonomy product.
  4. If the category tag is a Salesforce CRM tag (e.g. "Customers", "Administration") that doesn't correspond to any product, set the mapping to null to exclude these from the denominator.
"No matches above X% threshold"

Meaning: Keywords exist, product filter isn't the issue — but the best fuzzy match score is below the threshold (default 80%).

Fixes (in order):
  1. Open synonym_review.html, load the Keyword Recommendations sheet — look for near-misses at 75–79% for this URL's keywords. Add as synonyms.
  2. Open unmapped_review.html → Synonym action — type the correct topic synonym directly for this row.
  3. If many URLs share the same boilerplate phrase that's confusing the matcher, add it to Noise Phrases tab to filter it out.
  4. If the article covers a topic not yet in the taxonomy, raise a taxonomy gap request (see Gap Analysis → Never-Matched sheet).
  5. Last resort: if the content is genuinely off-topic (product marketing, release notes, etc.) and can't be mapped, use Remove in unmapped_review to exclude it from the denominator.
⚠️
Always use Gap Analysis for match rate — not the Console log. The Console log shows per-row match rate (which inflates if articles have multiple products). The Gap Analysis report shows per-unique-URL match rate — use that as the target metric.

Common mistakes & how to recover

Semantic and taxonomy files are swapped

Symptom: "0 matches" or bizarre error about missing columns (URL / Topic 1 not found).

Fix: GUI Setup tab → click Swap Files button, then re-run.

Match rate looks low but the output has many rows

Symptom: Console says "73% matched" but Gap Analysis says "61%".

Cause: Console shows per-row rate; multi-product Salesforce articles inflate the row count. Gap Analysis counts unique URLs. Always use Gap Analysis as the authoritative metric.

Hundreds of "Product filter excluded" for an unknown product name

Symptom: Unmapped_Reason = Product filter excluded matches (semantic Product: Adsolut_KMO_beheer) on many rows.

Cause: A Data_Categories__c value from Salesforce has no entry in category_mapping.json.

Fix: GUI Category Mapping tab → Add Row with the Salesforce value and the correct taxonomy product → Save → re-run.

Adding a synonym has no effect

Symptom: You added a synonym but the URL is still unmapped after re-running.

Possible causes:

  • The synonym is a multi-word phrase but the keyword is a single word (single-word terms can't match multi-word synonyms by design).
  • The keyword is being filtered as noise before matching — check the Noise Phrases tab.
  • The article's product still doesn't match the taxonomy product — the product filter runs after synonyms.
  • The match score is still below threshold — try a shorter, more distinctive synonym.

Debug: Enable Debug Mode in GUI Setup tab → re-run → check Console for per-keyword trace output for the affected URL.

Accidentally overwrote synonyms.json

Fix: Backups are created automatically before every patch is applied. Find the most recent synonyms_backup_YYYYMMDD_HHMMSS.json in countries/{CC}/ and rename it back to synonyms.json.

Country not showing in the Setup tab dropdown

Cause: Country is missing or disabled in config.yaml.

Fix: Open config.yaml, find the country entry, ensure enabled: true and the country code is uppercase (e.g. DE:). Restart the GUI.

Gap Analysis report shows phantom topics

Meaning: Topics that appear in the match output but don't exist in the current taxonomy file. Usually caused by running the matcher with an old taxonomy and then loading a newer taxonomy in the report generator.

Fix: Ensure both the matcher and the report generator use the same taxonomy file. Re-run the match with the current taxonomy.

Salesforce CSV Import

What the Import SF CSV button does, the file it expects, and how to configure it

The 📥 Import SF CSV button (Setup tab) converts a raw Salesforce Knowledge export — a 482-column CSV full of HTML metadata — into a clean semantic carriers file that the matcher can use. It handles URL extraction, Lightning URL conversion, keyword extraction from content, and multi-product row expansion automatically.

The pipeline

Salesforce Knowledge export
In Salesforce: Reports → Knowledge Articles → Export as CSV
Result: Knowledge__kav_*.csv — 482+ columns, ~6 useful
Click 📥 Import SF CSV
Setup tab → Import SF CSV → select file + country code → click ▶ Import CSV
Optionally select a Taxonomy file to rank keywords by relevance
Auto-processing (takes ~10–30s)
Extracts URLs from HTML anchor tags · converts Lightning URLs to public community URLs · expands multi-product rows via Data_Categories__c · extracts Keyword 1–12 from Title + Summary + Answer__c
Output: Semantic_{CC}_{datetime}.xlsx
Clean file: URL · Title · Summary · Description · Product · Keyword 1–12
Auto-populated as the Semantic File in Setup tab
Click Run Matching
Semantic file already populated → just click ▶ Run Matching
Output: taxonomy_match_{CC}_{datetime}.xlsx

CSV file spec — what the importer looks for

The importer auto-detects columns by name. Only these columns matter — the other 476+ are ignored.

Column name in CSV Required? Used for Notes
Knowledge_Url__c Required Article URL Often contains HTML anchor tags — URL extracted automatically. Lightning format auto-converted.
Title Required Keyword extraction Title keywords get a lower fuzzy threshold (source-aware matching) — higher chance of matching
Summary Recommended Keyword extraction 2–3 word phrases only (no single words). Pass --use-summary or check "Use Summary" in GUI.
Answer__c or Description__c Recommended Keyword extraction Article body. Boilerplate Dutch UI phrases filtered automatically via NOISE_PHRASE_STARTS.
Data_Categories__c Recommended Product assignment Semicolon-separated Salesforce categories e.g. Adsolut_Account;ExpertM_Plus. Mapped to taxonomy products via category_mapping.json. Without this column, product filtering is skipped.
⚠
BOM and column order: Both are handled automatically. You don't need to clean the CSV before importing — the importer strips byte-order marks from headers and detects column positions regardless of order.

Key behaviours during import

Lightning URL conversion

Salesforce internal URLs look like /lightning/articles/Knowledge/{slug}?language=nl_BE. The importer converts these to the public community URL automatically using country-specific base URLs:

CountryPublic base URL
BEhttps://taasupport.wolterskluwer.be/customers/s/article
NLhttps://wktaaeu.my.site.com/nlcommunity/s/article
SEhttps://wktaaeu.my.site.com/se/s/article

Multi-product row expansion via Data_Categories__c

If an article belongs to multiple products, Data_Categories__c contains multiple values separated by semicolons. The importer splits these and creates one row per product:

Input (1 row): Data_Categories__c = "Adsolut_Account;ExpertM_Plus"
Output (2 rows): Product = "Adsolut boekhouding"  ·  Product = "ExpertM"

Each row is then matched independently — one article can genuinely map to topics across multiple products.

category_mapping.json — mapping Salesforce categories to taxonomy products

The Data_Categories__c values (e.g. Adsolut_Account, ExpertM_Plus) are Salesforce internal names — they don't match taxonomy product names directly. countries/{CC}/category_mapping.json maps them:

"Adsolut_Account": "Adsolut boekhouding"
"ExpertM_Plus": "ExpertM"
"Customers": null ← null = exclude from denominator (Salesforce CRM tag, not a product)

Edit via GUI Category Mapping tab (visual table editor) or directly in the JSON file. Each country has its own file — Salesforce category names differ between BE, GB, and NL.

💡
Missing mapping = product filter excluded. If a Data_Categories__c value has no entry in category_mapping.json, those articles will appear in the output as "Product filter excluded matches". Add the missing entry in the Category Mapping tab and re-run. This is the single highest-yield fix when match rate is low.
